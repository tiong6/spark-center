# 工單：介面文字減法（說明收進 ⓘ、結論留畫面、三處圖形化）

執行者：任一模型或 Codex。審收者：Claude。審收方式見文末，執行者的自我回報不作數。
專案規則見 `CLAUDE.md`（改動流程、check.sh、中英字串表同步、不提舊名）。

## 為什麼

使用者 2026-10-17 的判斷：「文字過多，需要多一些圖形化減法」。量測（`tools/measure_prose.mjs`，中文介面，真機）：

| 分頁 | 可見說明文字字數 | 占該頁可見字 | 面板數 |
|---|---|---|---|
| 硬體 | 2,793 | 40% | 17 |
| 更新 | 1,715 | 48% | 6 |
| 設定 | 1,676 | 65% | 15 |
| 監控 | 529 | 67% | 2 |
| 其他五頁 | 各 ≤ 200 | — | — |

「可見說明文字」定義：`.sub1 / .sub / p / .muted / .empty` 元素，不含表格儲存格、FAQ 內文、彈出視窗。

## 目標

第一眼只看到資料與結論；「為什麼／從哪來／怎麼判定」一步就能看到，但預設不占版面。

數字目標（審收會重量）：硬體、更新、設定三頁的可見說明文字各減至 **現值的 50% 以下**；監控減至 300 以下。其他頁不動。

## 三類文字，三種處理（判斷規則，審收逐段對）

| 類別 | 例子 | 處理 |
|---|---|---|
| **A. 來源／判定方法說明** | 硬體頁開頭「來源：/sys DMI、lscpu、nvidia-smi…」（180 字）；fwupd「版本對不上」解釋（142 字）；npm「可信度怎麼判斷」（147 字）；網路鄰居「被動查詢，不掃描…」（138 字） | **收進 ⓘ**。正文整段移除，面板標題旁放一個 ⓘ，點開顯示原文。字串 key 不改、不刪。 |
| **B. 誠實標註與風險** | 「強制重開機」「推測」「只代表和本機通訊過，不代表有沒有上網」「GPU 上限再高實測沒作用」 | **結論留畫面、理由進 ⓘ 或 title**。結論壓成一個帶色標籤或一句 ≤ 20 字；完整理由放該標籤的 title 與 ⓘ。**不准整段藏掉**。 |
| **C. 設定頁的「給你什麼／付出什麼」** | 每個開關的 gives / costs | **不減字，改版面**：兩欄固定格式（左「給你」右「代價」），各自獨立一行，掃讀用。字數可以不變。 |

分不清 A 還是 B 時當 B 處理（寧可多留一句）。

## 機制：一個共用的 ⓘ 元件（照做，不要另想）

- 放在 `static/js/core.js`，全站共用；不新增外部套件。
- 標記：`<button class="info" data-info="<i18n key>" aria-label="…">ⓘ</button>`。樣式沿用現有 `.montools .info`（app.css 第 222 行），抽成全域 `.info`，monitor 的那個改用同一個，不留兩套。
- 行為：**點擊開啟**（觸控與鍵盤可用）、滑過也開啟、再點或 Esc 或點外面關閉、同時只開一個。開啟的是一個絕對定位的小面板（`.infopop`），寬 ≤ 420px，內容用 `t(key)`，允許 `faqRich` 那種輕量標記（清單、`反引號`）。
- 面板位置：ⓘ 下方，靠右邊緣時往左翻，不超出視窗。
- 面板內容可以放 `data-faq` 連結跳 FAQ（機制已有）。
- 字串：原本正文用的 key 直接拿來當 ⓘ 內容，**不要複製一份新 key**。中英兩邊自然都有。

## 三處圖形化（更新分頁）

1. **更新流程列**：把「模擬相依 → 留舊版 → 安裝 → 不重開」畫成四格靜態步驟列，放在清單上方取代現在的說明句。樣式沿用工作卡的 `#jobphase` 三段式（`.done/.cur`），加第四格「不會重開機」用 `--accent` 標。
2. **Dashboard 對照**：現在是一句長句（「等同一次做完 升級 18 · 韌體 0 · 強制重開機，而且不顯示清單。Dashboard 用 aptdaemon…」）。改成兩張並排小卡：左「DGX Dashboard 會」（升級 N、韌體 N、強制重開機紅標、略過分階段 N）、右「這裡你會」（勾了 N、動到 N、不重開綠標）。數字用現有的 `dashboard` 與 `state.selected`，一個字都不要新編。`dashboard_note` 那段長文進左卡的 ⓘ。
3. **分階段策略**：三選一 `<select>` 改成分段按鈕（segmented control），三格文字維持 `updates.phased_policy_*`；說明只顯示**選中那格**的一行 `phased_policy_hint_*`，其餘藏；「目前由哪個檔設定」「全機設定、會跳密碼」兩句進 ⓘ。

圖都是手寫 inline SVG 或純 CSS，和專案慣例一致。

## 不准做的事

- 不准刪 B 類的結論（強制重開機、推測、不代表有沒有上網、再高沒作用）。藏理由可以，藏結論不行。
- 不准改任何 API 回傳、不准動 server.py 的判定邏輯；這是純前端版面工單。
- 不准新增字串 key 來複製既有內容；搬位置用同一個 key。可以**刪**不再用的 key（中英一起刪，`tools/check.sh` 會對齊）。
- 不准用外部套件、CDN、tooltip 函式庫。
- 不准只做 hover：觸控與鍵盤要能開。
- 確認視窗（更新、降回、npm 計畫）與 FAQ 內文不在範圍。
